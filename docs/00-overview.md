# 从零开始读懂 KJS：一篇给小白的引子

你不需要懂编译器、不懂 Kotlin、甚至不懂"虚拟机"也能看明白这篇。我们从一个最朴素的问题开始，一层层往上搭。后面每一篇都会"从最简单的讲起"，读不懂就回到对应步骤。

## 第 0 步：程序到底是什么？

你写的 JavaScript 代码，本质就是**一段给计算机看的"指令清单"**（一堆文字）。比如：

```
1 + 2 * 3
```

计算机看不懂这段文字本身，它只认自己底层的"机器语言"。所以必须有人把这段"人话清单"变成"计算机能一步步执行的东西"。干这件事的程序，叫**引擎（engine）**。KJS 就是一个用 Kotlin 写的小引擎，专门跑 JavaScript。

## 第 1 步：引擎怎么把"文字"变成"能跑的东西"？

想象你拿到一份法文菜谱（你的 JS 代码），但厨师只懂中文。你有两个办法：
- **办法 A（先翻译菜谱）**：先把法文菜谱完整翻译成中文菜谱，厨师照着做。
- **办法 B（现场口译）**：雇个翻译，厨师做到哪步，翻译就念哪步。

KJS 两个办法都备了：
- **办法 A = 编译器（Compiler）**：把 JS 一次性翻译成一种"中间菜谱"——叫**字节码（bytecode）**。
- **办法 B = 树遍历解释器（Walker）**：直接边读 JS 边执行，不翻译。

默认走办法 A（更快，还能再加速，见后面 JIT）。办法 B 留着做对照、验证正确性——同一段代码两种办法跑出来结果一致，就说明没写错。

> **为什么要有"中间菜谱"（字节码）这一步，而不是一次性翻成机器语言？** 因为机器语言跟具体电脑绑定，而字节码是"通用的中间语言"，由一个叫**虚拟机（VM）**的程序来逐条"照着做"。这样同一份字节码，在任何装了 KJS 的地方都能跑。这就像"世界语菜谱"——不管哪个国家的厨师，只要他懂世界语，就能照做。

## 第 2 步：虚拟机（VM）和"栈"是什么？

**虚拟机**就是一个"照着字节码清单一步步做"的程序。字节码里的每一步都超级简单，比如：
- "把数字 3 放到盘子里"
- "把盘子最上面的两个数拿出来相加，结果放回盘子"

注意这里有个关键东西：**盘子**。计算机做运算时需要个临时放数的地方。KJS 用的是一个叫**操作数栈（operand stack）**的结构——你可以把它想成一摞盘子：**只能从最上面放、从最上面拿**（这叫"后进先出"）。为什么用盘子？因为数学运算天然就是"拿两个数、算一下、放回去"，盘子正好匹配这个节奏。

> 所以"栈式虚拟机"= 一个"照着简单清单一步步做、临时数字都放在一摞盘子里"的程序。就这么简单。

## 第 3 步：亲手走一遍 `1 + 2 * 3`

下面把前面串起来，看 KJS 怎么算出 7。

### 3.1 第一步：词法（Lexer）——把文字切成"词"

源码 `1 + 2 * 3` 先被切成一段"词"：
```
数字(1)  加号(+)  数字(2)  乘号(*)  数字(3)
```
（"词法"就是"分词"，像把句子切成单词。）

### 3.2 第二步：语法（Parser）——搞清楚结构

接下来要明白"先乘后加"。KJS 把代码整理成一棵**语法树**：把 `2*3` 先绑成一组，再和 `1` 相加。就像数学里先算括号里的——这里用"树"表达谁先算。（语法树只是内部用来记结构的，你不用管它长啥样，知道"编译器靠它知道先算谁"就够了。）

### 3.3 第三步：编译（Compiler）——变成字节码清单

编译器把语法树翻译成字节码（那条"中间菜谱"）。`1+2*3` 变成：

```
0  放数字 1        ← 把 1 放进盘子
1  放数字 2        ← 把 2 放进盘子
2  放数字 3        ← 把 3 放进盘子
3  相乘            ← 拿 3 和 2，算 6，放回盘子
4  相加            ← 拿 6 和 1，算 7，放回盘子
5  存结果 / 结束
```

注意盘子的变化：
```
执行前：        [ ]
放 1 后：       [1]
放 2 后：       [1, 2]
放 3 后：       [1, 2, 3]
相乘后（拿3、2）：[1, 6]
相加后（拿6、1）：[7]
```
最后盘子里剩 7，就是答案。

### 3.4 第四步：执行（VM）——虚拟机照做

虚拟机就按上面清单一行行做，盘子变化如上，最后得到 7。

## 第 4 步：整体架构（一张地图）

把上面所有角色摆在一起：

```
你的 JS 代码
   │
   ├─ 词法(Lexer)：切成"词"
   ├─ 语法(Parser)：整理成"语法树"（谁先算）
   ├─ 编译(Compiler)：变成"字节码"
   └─ 执行(VM)：照字节码一步步算，数字放"盘子"里
```

另外还有几个"配角"：
- **全局环境（Realm）**：装着所有全局变量（像 `console`、`Math`）和内置功能。
- **运行时值模型**：JS 里的数字、字符串、对象在 KJS 内部怎么表示（数字存成浮点数，对象是一个"属性盒子"等）。
- **JIT（即时编译）**：发现某段代码跑得勤，就把它直接变成更快的机器码（像把常用菜谱背下来，不用每次现翻）。
