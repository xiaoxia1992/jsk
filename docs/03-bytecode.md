# 字节码与指令集（白话版）

> 前置随便翻翻：总览篇讲了"字节码就是一份中间菜谱"。本篇就把这份菜谱长什么样、怎么存、怎么造出来讲清楚。

## 第 1 步：字节码到底是什么？

回顾一下：你的 JS 代码经过"编译器"，变成一份**字节码（bytecode）**。它是一份很简单的指令清单，给虚拟机（VM）照着一步步执行。

比如 `1 + 2 * 3` 变成的字节码大概长这样（右边是注释）：

```
0  放数字 1
1  放数字 2
2  放数字 3
3  相乘
4  相加
5  存结果 / 结束
```

每一条都只有一个"动作"，没有任何花里胡哨的逻辑。VM 就一行行往下做。

## 第 2 步：清单在电脑里怎么存——三条并排的数字列

电脑不懂"放数字 1"这种文字，它只认数字。所以 KJS 把这份清单存成**三个并排的数字表格（数组）**，就像 Excel 的三列：

| 列名 | 存什么 | 例子（对应上面那条清单） |
|---|---|---|
| `code`（第 1 列） | 每一步的"动作编号" | `放数字` 是几号、`相乘` 是几号…… |
| `aOps`（第 2 列） | 这个动作需要的"第一个参数" | `放数字 1` 里的 `1` |
| `bOps`（第 3 列） | "第二个参数"（大部分指令用不到） | 空着 |

**三列同一行号 = 同一条指令**。比如第 0 行：第 1 列写着"放数字"的编号，第 2 列写着 `1`。VM 读的时候，就看第 `i` 行的三列，就知道"第 i 步干啥、参数是啥"。

为什么用"三列"而不是"每行做成一张卡片"？因为一排排整齐的数字数组，电脑读起来飞快、还不用来回创建对象。这是 KJS 为了求快做的小设计。别的引擎（比如 V8、QuickJS）大多用"一条字节流、参数紧跟在操作码后面"的写法，思路类似，只是排版不同。

除了这三列，还有几个"池子"存复用的值：
- **常量池**：数字、布尔这类固定值（如 `3.14`），相同的值只存一份。
- **字符串池**：变量名、属性名等文字，相同名字只存一份。
- **子函数池**：函数里再定义的函数（见第 6 步）。

## 第 3 步：常量池为什么要"去重"

同一个数字、同一个字符串在代码里可能出现很多次。`constIdx` / `strIdx` 这俩函数负责：要存一个新值前先看看池子里有没有一样的，有就直接复用下标，没有才新增。好处是省内存，也方便后面做"形状比较"的加速。

## 第 4 步：emit 与跳转修补（最容易懵的地方）

编译器一边从上往下扫代码，一边往清单末尾"加一行"，这个动作叫 **`emit`**（发射）。

麻烦出在 `if` / `for` 这类带"跳转"的指令：它要跳到的"目标行号"，在**写它那会儿还不存在**（目标在后面才生成）。于是编译器：
1. 先 `emit` 一条跳转，但目标先填个**占位**（比如 0）——"先占个坑"；
2. 继续往下编译后面的代码；
3. 等知道了真正的行号，再用 **`patchA`** 把那行的占位改成正确行号。

打个比方：写菜谱时先写"转到第 ___ 步"，等后面步骤写好了，再回去把空白填上。`patchB` 同理，只是改第二列的参数（用得少，比如 `try/catch` 要同时记 catch 和 finally 两个位置）。

> 纪律：占完坑必须立刻记下"这是第几行"，因为后面每加一行，行号总数都在变，晚一步就找不到坑在哪儿了。

## 第 5 步：freeze（定稿）

编译器一边在"可变的清单"上写。全部写完后，调用 `freeze`：把可变清单**冻结成只读的定稿**（真正的 `IntArray`），交给 VM 高速读取。子函数也一起冻结。冻结之后这份字节码就不变了，多个地方同时跑也安全。

## 第 6 步：函数是独立单元（为什么主清单里看不到子函数）

每个 JS 函数（包括最外层那段程序）都编译成**自己独立的一份字节码**。子函数不塞进父函数的清单里，而是放进父字节码的"子函数池"，父清单里只留一条 `MAKE_CLOSURE`（意思是"按池里第几号造个函数"）。

所以变量名在编译期就被擦成了"第几号格子"（槽号），而且**槽号只在各自函数内部有效**。比如子函数里的 `x` 占它自己的 0 号格，跟外层毫无关系。局部变量是"函数的私有财产"，不会漏到父清单里。

想看子函数的真实指令，调用反汇编（见第 7 步）会把它也打印出来。

## 第 7 步：反汇编（disasm）

`disasm` 把那份数字清单还原成能读的文字，方便调试。它会顺便把"池子下标"翻译成真正的常量/名字，并打印每个函数的指令。

## 第 8 步：指令集总览（都有哪几类动作）

KJS 一共约 70 条指令，按干的事分成几类（每类一句话）：

- **放常量 / 字面量**：放数字、放字符串、放 `true/false/null/undefined` 等。
- **局部变量 / 参数**：从某个格子读出来（`LOAD_LOCAL`）、写进某个格子（`STORE_LOCAL`）。
- **名字解析**：读/写全局变量、读/写闭包捕获的变量。
- **属性 / 元素**：`obj.x` 的读和写、`obj[key]` 的读和写、删属性、造对象、造数组、造函数。
- **栈操作原语**：复制栈顶（`DUP`）、弹掉栈顶（`POP`）、交换栈顶两个（`SWAP`）。
- **算术 / 逻辑 / 比较**：加減乘除、取负、比较大小、相等判断等。
- **控制流**：无条件跳、条件跳（真跳/假跳）。
- **调用 / 返回**：调用函数、用 `new` 创建实例、返回结果。
- **异常 / 迭代 / 作用域围栏 / 顶层结束**：`throw`、`try`、循环遍历、块边界、程序结束。

下面这张大表把**每条指令对"盘子（栈）"和"格子（局部变量）"的精确操作**列出来——这是本篇最该收藏的部分。

## 第 9 步：逐指令参考表（栈 / 局部变量 / 池 的精确语义）

> **约定**：
> - 表内 `…` 表示盘子底部不动的部分，右边是栈顶；`[…, x, y] → […, z]` 表示"执行前 / 执行后"。
> - **KJS 的赋值是一条表达式**：`STORE_*` 系列执行后**把被赋值的值留在盘子顶**（读一下但不弹走），所以独立的赋值语句通常要在 `STORE_*` 后紧跟一条 `POP` 把残留清掉。只有 `DECL_GLOBAL` 是真正弹出初值的例外。
> - `locals[格]` 若存的是"闭包盒子"，读写走盒子里的值。
> - 算术/比较结果类型：数值运算得数字，比较得布尔；`加` 任一边是字符串就变成拼接。
> - 跳转指令的 `a` 是**绝对行号**（写的时候先占位，编译完由 `patchA` 回填）。

| 指令 | A/B | 作用 | 栈变化 | 副作用 |

## 第 10 步：设计取舍（为什么这么设计）

- **三条并排数组而非"每行一个对象"**：连续内存 + 数字编号查表，是性能内核；代价是"跳转修补"要显式管理（第 4 步）。
- **A/B 双参数固定布局**：所有指令统一读 a/b 两列，少数双参数指令自然复用。
- **常量池去重**：相同字面量只占一格，省内存也利于加速。
- **freeze 成只读**：编译完后字节码不变，VM 可放心多人同跑，无并发写风险。

## 第 11 步：常见坑

- **补丁点要立刻记行号**：占完坑若又加了别的指令，`code.size-1` 就指向错行，跳转目标错乱。务必"占坑后立即记录行号"。
- **池去重依赖相等判断**：自定义值若没正确实现"相等"比较，会重复入池或配错。
- **freeze 前不可执行**：VM 读的是冻结后的数组，未冻结时为空。
- **`caches` 是运行期状态**：不跟随 freeze；同一份字节码被多个函数并发执行时，缓存要线程安全。
