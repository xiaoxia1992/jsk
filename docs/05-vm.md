# 虚拟机：字节码怎么跑起来（白话版）

> 前置：字节码篇讲了"清单长什么样"，编译器篇讲了"清单怎么造出来"。本篇讲清单怎么被一行行执行，以及函数调用、闭包、异常这些是怎么实现的。

## 第 1 步：VM 的核心就是一个大循环

虚拟机的心脏是一个"读一条、做一条"的循环：

```kotlin
while (true) {
    val op = code[pc]          // 读当前行的"动作"
    when (op) {                // 根据动作分派
        Op.LOAD_LOCAL  -> { ... }
        Op.ADD         -> { ... }
        // ……每条指令对应一段处理
    }
    pc++                       // 走到下一行
}
```

`pc`（program counter，程序计数器）就是"现在读到第几行"。每条指令处理完，`pc` 前进一步；遇到跳转指令，`pc` 直接跳到目标行。

注意：VM 内部没有"函数栈帧的链表"，因为 **Kotlin 自己的调用栈就是栈**。每次调用一个 JS 函数，就真的调用一次 Kotlin 函数 `runFrame`，`runFrame` 里再 `runFrame`——天然一层套一层，和 JS 的函数嵌套一模一样。

## 第 2 步：一次"函数调用"需要记住哪些东西（Frame）

每调一个 JS 函数，VM 要准备一份"这次调用的档案"，叫 **Frame（帧）**。它装着：

- **盘子（stack）**：临时放数字的地方（字节码篇第 2 步讲过的"一摞盘子"）。
- **格子表（locals）**：这个函数自己的局部变量（编译器篇大招一说的"第几号格子"）。
- **实参数组（args）**：调用时传进来的参数。
- **this**：这个函数是"谁的"（`obj.f()` 里 `this` 是 `obj`）。
- **闭包盒子（upvalues）**：记住外层变量的那些盒子（编译器篇大招二）。
- **pc**：现在读到第几行。

Function Frame（普通函数调用的档案）从"格子池/盘子池"里借两块空数组来用，用完好归还，省得每次都 new。

## 第 3 步：函数怎么调用、参数怎么传

你写 `f(a, b)`，VM 大概这么干：
1. 把 `f`、再把实参 `a`、`b` 依次压进盘子；
2. 遇到 `CALL 2`（2 个参数）：弹走 2 个实参 + 弹走函数 `f`；
3. 新建一份 Frame，把实参装进 Frame 的 `args`，跳到 `f` 的字节码开头开始跑。

返回值会被压回盘子，调用方用 `LOAD_LOCAL` / `STORE_LOCAL` 之类的指令接住。

> 一句话：**调用 = 弹走函数和参数 → 开新 Frame → 从函数开头跑 → 返回值压回盘子。**

如果是 `obj.f()`（方法调用），用的是 `CALL_METHOD`：多弹一个 `obj` 作为 `this`，这样函数里访问 `this` 才指向 `obj`。

## 第 4 步：闭包盒子怎么被读写（回顾）

编译器篇讲过关子：`inner` 用到的外层变量 `x` 被装进一个共享盒子。跑到 VM 这层：
- `STORE_LOCAL` 发现格子其实是盒子时，改成"写进盒子里"；
- `LOAD_UPVAL` 从盒子里读。

这个盒子存在 Frame 的 `upvalues` 里，外层函数返回后盒子不销毁（因为内层函数还拿着它），所以 `inner` 以后还能用 `x`。

## 第 5 步：全局变量、属性访问、内联缓存

- **全局变量**：`LOAD_GLOBAL` / `STORE_GLOBAL` 直接读写"全局环境"里的绑定，不是局部格子。
- **属性访问 `obj.x`**：`LOAD_PROP` 先去 `obj` 上找 `x`；找不到就沿"原型链"往上找（架构篇讲过原型链）。
- **内联缓存（IC，加速）**：属性访问很频繁。VM 会"记性很好"地缓存"上次 `obj.x` 的 `x` 在哪儿找到的"，下次同类访问直接去那，省得每次从头找。这就是"内联缓存"——把上次的查找结果当场缓存下来。

## 第 6 步：控制流：条件、循环怎么跳

字节码篇第 9.7 节列了跳转指令。VM 里它们就是改 `pc`：
- `JMP a`：`pc = a`（无条件跳）。
- `JT a`：弹一个值，为真就 `pc = a`。
- `JF a`：弹一个值，为假就 `pc = a`。
- `JT_KEEP` / `JF_KEEP`：看栈顶值决定跳不跳，**跳的时候把值留在盘子里**（用于逻辑与/或的短路：`a && b` 里若 `a` 假，直接拿 `a` 当结果，不再算 `b`）。

`if` / `for` / `while` 在编译器篇就被翻译成这些跳转 + "跳转修补"，VM 只管按 `pc` 跳。

## 第 7 步：异常怎么接住（throw / try）

VM 用一个"处理器栈"记录当前有哪些 `try` 在等着接异常：
- 进入 `try`：emit `TRY_ENTER`（记下 catch 位置、finally 位置、当前盘子高度），压一条处理器记录。
- 抛异常 `THROW`：VM 沿处理器栈找最近的 `try`，把 `pc` 跳到它的 catch；若有 finally，先跑 finally。
- 离开 `try`：emit `TRY_EXIT`，把处理器记录弹掉。

这样异常就能像 JS 那样一层层往外抛，直到被某个 `catch` 接住或变成未捕获错误。

## 第 8 步：循环遍历（for-in / for-of）

`for (k in obj)` 和 `for (v of arr)` 不是一条神奇指令，而是几步配合：
- `FOR_IN_INIT`：把 `obj` 的"键列表"做成一个遍历状态，压进盘子。
- `FOR_IN_NEXT a`：每次循环看状态，还有键就压下一个键；取完了就跳到 `a`（循环结束）。
- for-of 同理，只是压的是"值"而不是"键"。

## 第 9 步：算术、比较、字符串拼接

- 二元运算（`加/减/乘/…`）：弹两个值，算出结果压回。若 `加` 的任一边的字符串，就变成拼接。
- 比较（`等/小于/…`）：弹两个值，压布尔结果。
- 一元（`取负/取反/typeof/…`）：弹一个值，压结果。

数字在 KJS 内部统一存成浮点数（编译器篇提过），所以 `1 + 2` 其实是 `1.0 + 2.0`。

## 第 10 步：程序怎么结束

最外层程序也是一个 Frame。它把每句"顶层表达式"的结果用 `STASH_RESULT` 暂存，最后 `HALT` 以这个暂存结果作为整段程序的返回值，VM 停。这就是你在 `kjs` 命令行看到的那行输出。

## 第 11 步：JIT 在哪里插进来（预告）

当某段字节码跑得特别勤，VM 会把它交给 JIT 编译器，直接翻成更快的机器码（见 JIT 篇 08）。但 VM 的主循环、Frame、盘子这些概念不变——JIT 只是"把这层简单解释换成更快的执行方式"。

## 第 12 步：常见坑 / 设计取舍

- **盘子深度要配对**：`emit` 一条"压 2 弹 1"的指令时，必须保证调用前盘子里真有 2 个；否则 `pop()` 会拿到错的值。
- **`JT_KEEP` / `JF_KEEP` 跳走时留值**：用它们实现短路时，落空分支要记得把栈顶多余的值弹掉，否则盘子会多出垃圾。
- **Frame 借用要归还**：函数返回前必须把借来的盘子/格子数组还回池子，否则内存一直涨。
- **异常路径也要清栈**：`throw` 后处理器栈、`finally` 的清理都得走完，否则状态脏掉。
